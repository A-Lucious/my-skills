# 制作流程

这份流程说明一张像素素材怎样从需求走到成品：先弄清楚要画什么，再把形体和光照做清楚，用固定风格 Shader 生成并预览像素底稿，经 Aseprite 整理大色块、补材料细节，最后检查整体效果。

风格和分类从[技能入口](SKILL.md)选择；评审方式、文件命名和交付格式见[交付规范](specs/production.md)。这里按制作顺序展开具体操作。

## 开始前：把这次要画的东西弄清楚

1. **读懂用途。** 用一句话描述目标，例如“画一个能放在背包里的打开宝箱图标”或“画一张能看清表情的年轻旅人头像”。确认交付的是静态图、动画还是场景插图，以及它会显示在什么位置。
2. **看相关参考。** 打开原图和局部，观察主体大小、观察角度、颜色分区、明暗和细节密度。记下本次要借鉴的具体特征，例如箱盖的倾斜角度、纸框的轻薄感、头像的五官比例。
3. **列出关键内容。** 写清有哪些部件、谁挡住谁、哪些特征需要一眼认出，以及用户允许省略什么。箱子要看开口和箱盖，头像要看朝向与表情，场景要看事件焦点和前后层次。
4. **确定画布和制作方案。** 选好原生尺寸，也就是 PNG 本身的像素大小；再确定观察角度、材料、所用色系和光照计划。将这些内容写进任务卡，后面修改时有依据可查。

Blender 通道默认从第一步开始，完成六个阶段；纯 2D 通道按技能入口的 B 轨策略 1 执行。只有用户提示明确说明不需要某阶段时才可额外省略；任务卡引用对应原话并列出省略范围，未说明时记录“无阶段省略授权”。素材分类、平涂风格、尺寸小或制作简单不能作为省略理由。

第一、二步通过真实 Blender MCP 调用完成，并保存 `.blend`、相机与光源记录、渲染预览及指导数据；文字光照计划或直接计算 2D 像素明暗不能代替这两个阶段。上游必需产物缺失或工具调用失败时，该阶段仍未完成，先修复或明确报告阻塞，不得自行改走纯 2D 流程。

## 阶段完成条件

产物生成后实际打开检查，写清所用版本、证据路径、具体观察和剩余问题。完成本阶段制作与自检后，按交付规范执行用户阶段评审；合并评审不免除下表中的自检。

| 阶段 | 进入后续制作前必须确认 |
|---|---|
| 1：3D 与相机 | 目标尺寸剪影中的主要比例、关键部件、连接位置与空隙成立；记录供像素稿对照的结构基准 |
| 2：光照渲染 | 实际渲染与部件/材质、法线、深度数据对应同一场景及相机；读取数据样本，确认含义与画面一致，不能只有配置清单 |
| 3：风格 Shader 预览 | Blender MCP 直接执行所选风格目录的固定脚本，保存原生底稿、同视角前后对照、脚本版本/哈希及参数；先向用户展示当前效果，记录 Q3 评审，再进入第四步 |
| 4：像素粗稿 | 直接将第三步已确认的同一版原生 PNG 经 Aseprite MCP 导入作为底稿，再在 Aseprite 中实际修改为粗稿；在同一网格对照 3D 指导、导入底稿与修改后粗稿，主要比例、连接、孔洞及大明暗成立，形体问题未解决时不进入细化 |
| 5：细节与纹理 | 细化前后仍符合结构基准；声称完成的特征能在预期显示大小辨认，细节未破坏形体和明暗 |
| 6：最终检查 | 对最终同一版源稿及导出分别完成视觉与技术检查；展示候选并如实记录用户评审，未经确认保持待评审 |

像素抽象允许调整轮廓和放大识别点；逐项记录相对 3D 的有意偏差及其可读性依据。不能用“像素风”或“简化”笼统解释主要形体丢失、部件错接或对象身份改变。结构错误回到第一或第四步，光照错误回到第二步；不靠增加纹理或高光掩盖。

## 第一步：搭出 3D 草稿，选好观察角度

这一轮要解决的是：物体长什么样，从哪个角度能把它看清楚。

1. **把对象拆成几个主要部分。** 在 Blender 中搭出大形，例如箱体、箱盖、锁扣；或者头部、身体、手臂和装备。场景先搭地面、建筑和主要角色的位置。平面符号、纸框和剪影可用平面或浅挤出网格搭出轮廓、孔洞与层次，保持用户要求的平面视觉风格，仍完成相机与后续光照阶段。
2. **调整比例和连接。** 看部件之间的大小是否合适、连接是否自然、开合或姿态是否清楚。这个阶段先做影响画面的形体，细小花纹留到像素阶段。
3. **摆好动作和前后关系。** 角色先确定重心、四肢和装备的位置；建筑先确定屋顶、墙面和入口；场景先确定焦点及前中后景。
4. **调整相机。** 试几个角度，比较正面、侧面和顶部能看见多少。比如箱子从正上方看可能读不出箱体厚度，从过低的位置看又可能看不清开口，选择能表达本次关键特征的角度。
5. **按目标像素大小看剪影。** 先只看外形和空隙，检查锁扣、手臂、门洞等有没有挤在一起。特征太小或互相遮住时，调整部件大小、位置或相机，再看一次。
6. **保存这一版草稿和预览。** 给后续要分别处理的部件、材料做好标记，让下一步能够区分“这是箱盖”还是“这是金属带”。在目标网格记下本对象的结构基准：主要长宽比例、部件锚点、连接轴线或设计偏置，以及孔洞和关键识别点的位置；动画另记各帧共用锚点。只选能判定本次形体的项目，不套用统一比例。

**这一轮看什么（Q1）：** 对象是否一眼能认出，关键部件是否完整，比例、连接、姿态和观察角度是否合适。

**留下什么：** 3D 源文件、目标视角预览、目标尺寸剪影，以及相机和部件记录。

## 第二步：打光，看清哪里亮、哪里暗

这一轮要解决的是：各个面怎样表现体积，遮挡产生的影子应该落在哪里。

1. **按光照计划摆主光。** 设置光源方向、高度和软硬，再调环境光，让受光面与背光面都能看清。画面需要火焰、魔法等额外光源时，把它们放到对应位置。
2. **先观察大面的明暗。** 看朝光的一面、转过去的一面和背光的一面是否有清楚的区别。例如箱子的顶面、正面和侧面，需要能读出不同朝向。
3. **沿遮挡关系检查影子。** 逐个看“谁挡住了光，影子落在哪”。例如帽沿遮住额头、屋檐遮住墙面、箱盖遮住箱腔；再检查贴地位置和接缝处的暗部。
4. **检查完整画面。** 看主体、地面影和需要保留的背景有没有被裁掉。投影伸出了画面时，调整取景或补足展示范围，再生成预览。
5. **导出后续绘制用的指导图和数据。** 保存彩色渲染与 alpha，以及实际部件/材质 ID、法线、深度数据；需要判断投影时补实际照明或遮挡依据。可使用真实渲染通道或 Blender 目标网格射线查询，具体格式与完成条件见 [Blender MCP](mcp/blender.md)。对象名字、pass_index、灯光位置与相机参数属于配置，不能充当这些空间数据。
6. **查看实际导出的结果。** 对照渲染图和各项数据，确认它们能解释同一套形体与光照。读取数据尺寸、坐标定义和有代表性的像素样本，确认采样来自本轮实际模型，记录第三、四步具体使用了哪些字段。同一渲染可供第一、二步共用，但须注明复用并分别记录形体与光照结论；不同文件名不证明执行过不同步骤。

**这一轮看什么（Q2）：** 光向是否清楚，大面是否有体积，影子是否对应实际遮挡，接触位置和投影范围是否完整。

**留下什么：** 带光照的预览、原始指导数据，以及光源与数据含义的记录。具体导出方法见 [Blender MCP](mcp/blender.md)。

## 第三步：调用固定风格 Pixel Shader，先展示当前视角的效果

这一轮将第二步的实际渲染转成风格对应的像素底稿，让用户在 Aseprite 粗稿制作前看到 Shader 本身的效果。

1. **固定视角与输入。** 使用已确认的模型、活动相机、光照、帧、裁框和原生 W×H；记录所选风格及色系。用户指自由视窗时，先通过 Blender MCP 将该视角对齐到工作副本相机，再生成预览；不能悄悄改用另一个视角。
2. **直接执行风格脚本。** 加载 `styles/<style-id>/pixel_shader.py`，经 Blender MCP 在 Blender 内执行。不同风格使用各自的脚本；算法、阈值与色彩规则按版本固定，任务只提供画布、选定色系与对象用途等输入。Parchment Fantasy 调用与兼容性见 [Pixel Shader](styles/parchment-fantasy/PIXEL-SHADER.md)。没有对应脚本时先补齐并预览，不能套用另一风格或临时重写节点冒充固定脚本。
3. **保存真实结果。** 保留原始模型和第二步指导，在工作副本中输出原生像素 PNG、可编辑 `.blend`、同视角着色前后对照及调用清单。清单包含脚本路径、版本/哈希、色板版本/哈希、相机矩阵、引擎、目标尺寸和实际参数。放大展示不能代替原生底稿。
4. **检查并提前展示（Q3）。** 实际查看原生、整数倍放大和前后对照，核对形体、孔洞、材料颜色与大明暗；向用户展示效果及剩余问题。默认等待用户确认这版效果，再进入第四步；不能用 Agent 自检代替用户确认。明确的合并评审授权可沿用，但仍须在第四步制作之前展示 Shader 预览。脚本、色板、视角或关键参数变化后重出并重新展示受影响的效果。

**留下什么：** 原生像素底稿、同视角前后对照、像素化工作 `.blend`、Shader 调用清单与 Q3 状态。评审预览可经 Aseprite MCP 导入和整数倍导出，但此时不开始第四步的生产粗稿精修。

## 第四步：导入已预览的 Blender 像素底稿，整理 Aseprite 粗稿

这一轮明确分为两件事：**直接导入第三步已确认的原生结果作为底稿 → 在 Aseprite 中修改底稿，形成像素粗稿**。整理颜色、轮廓、识别点和大明暗时，保持上游形体与部件关系；只完成导入或另存文件，第四步仍未完成。

1. **核对制作输入与像素网格。** 使用第三步已预览的模型、相机、光照、裁框和目标 W×H，记录网格原点与部件锚点；与 Shader 调用清单一致。
2. **沿用已预览的原生底稿。** 使用第三步的同一版 Blender PNG，不在导入前悄悄换 Shader、色板或重新生成另一套效果。需要改输入时回到第三步重出并展示；引擎变化影响光照时重检 Q2。
3. **检查 Blender 直出图。** 确认 PNG 真正为目标 W×H，实际查看剪影、部件比例、连接、孔洞及亮暗面；大分辨率马赛克截图不能当作原生像素底稿。细部被采样抹掉或主体变形时，先在 Blender 调整模型、相机或网格并回到第三步重出，不另画一套主体替代。
4. **导入第三步结果作为底稿。** 将第三步已确认的同一版原生 PNG 直接交给 Aseprite MCP 的 `import_image`，建立可编辑 `.aseprite`；读取实际画布、帧与图层，确认尺寸及像素位置未变。保留原始 PNG，在源稿中保留未修改的底稿参考层，复制为粗稿工作层。随后通过 Aseprite MCP 在该工作层上执行第 5–7 项修改，形成粗稿，并记录底稿版本、实际改动及前后对照。用户明确要求其他粗稿方式时，在任务卡引用原话与范围；其他阶段仍按其授权执行。
5. **整理材料与固定色板。** 根据部件/材质指导，将底稿颜色整理到本次选定的固定色系与工作色阶，修正渲染插值色、半透明边缘和必要的局部轮廓。所有像素写入、调色与图层操作经过 Aseprite MCP；不能为迁就渲染色另造生产色板。透明及色系收敛后重新检查剪影与孔洞。
6. **补关键识别点。** 在底稿结构上整理眼睛、鼻子、锁扣、门洞、握柄等本次需要看清的内容。比较大小、间距和前后关系，必要时适度放大，并记录相对直出底稿的有意调整。
7. **整理大明暗。** 保留直出图中的主要受光、背光、投影与接触暗部，把连续渲染变化整理为连贯像素簇；结合原始法线和遮挡指导复核调整。平涂符号和纸框保持用户要求的平面色块层次。
8. **生成对照并实际查看。** 通过 Aseprite MCP 制作同网格的 3D 指导/Blender 像素底稿/当前粗稿对照，逐项核对第一步的结构基准。原生大小看主体与特征，整数倍放大看阶梯和连接，灰度看大明暗；记录保持项、有意调整和未解决问题。主要比例、连接或识别点失效时返工并重新对照，不进入第五步。

**这一轮看什么（Q4）：** 小尺寸是否清楚，部件与材料是否能区分，大明暗是否成立，整体比例和像素密度是否符合所选风格。

**留下什么：** 第三步原生 PNG 及像素化参数、保留底稿参考层和修改后粗稿工作层的 `.aseprite`、3D 指导/导入底稿/修改后粗稿的同网格对照、原生/放大/灰度预览，以及结构核对与实际改动说明。绘制和预览调用见 [Aseprite MCP](mcp/aseprite.md)。

## 第五步：补像素簇、材料细节和纹理，再检查明暗

这一轮是在粗稿上细化，让轮廓更自然、材料更明确，同时保持已经画清楚的大形。

1. **整理边缘。** 调整曲线和斜边的台阶，修正毛刺、挤在一起的部件和难读的小空隙。放大看像素排列，再回原生大小看改动是否有帮助。
2. **补材料结构。** 先补能说明材料和厚度的内容，例如书页边、金属带、布料褶皱、木板接缝、门窗边厚。检查这些细节是否顺着已有的面和部件关系。
3. **按需要加入纹理。** 在相应材料区域安排短线、小斑块、磨损或不均匀的接缝。“像素簇”就是几颗一起组成小形状的像素。木纹顺着板面，布料变化跟着褶皱，金属用更少的磨损和更窄的亮点；具体组织方法见[纹理规范](specs/texture.md)。
4. **比较细化前后。** 切换细节或纹理层，复核第四步的结构基准，看材料是否更清楚，主体、表情和关键部件是否依然好认。逐项检查计划中的识别特征是否真的出现在画面上；未实现或小尺寸不可辨认的内容如实记录，不凭设计名称宣称完成。发现某一区域变碎、变花时，删减或合并那里的像素簇，再看结果。
5. **做最后一轮明暗复核。** 查看彩色与灰度预览，重点找被细节破坏的关系：纹理是否切断投影边界，背光面是否被亮点抬得太亮，缝隙是否失去深度，高光是否顺着材料和面朝向。按[光照规范](specs/lighting.md)局部修正，再查看新预览。
6. **检查源文件。** 读取画布、图层、帧数、时长和动作标签，确认内容与任务一致。动画在这里查看各帧和播放效果，检查锚点、动作连接与逐帧明暗。
7. **导出候选并做技术检查。** 生成原生 PNG 或动画图集，检查尺寸、裁切、颜色和透明度；有动画数据时核对帧位置和时长。发现问题后修正对应源稿，再重新导出。具体检查方法见[交付规范](specs/production.md)。

**这一轮看什么：** 细节是否增加了有效信息，材料是否更明确，大明暗是否保持连贯，源文件和导出结果是否正确。

**留下什么：** 分层候选稿、细化前后与最终明暗预览、候选导出，以及技术检查结果。程序辅助纹理的种子和参数随这一版记录。

## 第六步：看整体效果，确认并交付

这一轮把成品放回实际用途里，判断它是否完成了最初的目标。

1. **重新对照需求和参考。** 对最终同一版源稿和实际导出检查对象身份、主要比例、连接关系、姿态或表情、关键部件、材料和风格；再次对照结构基准与开始前列出的关键内容。存在未解决的形体或识别问题时，视觉自检记录“需返工”，不能用色板合规、无杂点或工具成功替代，也不能声明“完全满足需求”。
2. **按实际使用大小查看。** 同时看原生图、整数放大图和预期界面比例。图标看一眼能否辨认，头像看表情，场景看焦点和事件；再检查留白与裁框。
3. **查看动画或临摹的额外结果。** 动画看正常速度下的动作和循环，临摹逐对象对照原图并查看比较报告。将具体问题记到对应对象或帧。
4. **把候选交给用户评审（Q5）。** 展示当前预览和可编辑源稿，说明本轮主要改动与剩余问题。技术检查、Agent 视觉自检和用户验收分别记录；用户未明确确认时 Q5 保持“待评审”，不能代填“通过”。第五步的内部细化检查不等于 Q5。需要修改时，按下方表格回到相应步骤。
5. **整理接受的版本。** 保存对应源稿、正式导出、最终预览、任务记录和检查结果，核对交付文件来自同一版。
6. **完成本次交付目标。** 任务包含游戏接入时，按交付规范更新素材引用，并在游戏窗口检查真实显示；仅制作素材时，交付对应文件和记录。

**留下什么：** 用户接受的版本、最终文件与预览、验收记录；有接入任务时附实际显示检查结果。

## 临摹和动画怎样走这套流程

**参考临摹：** 开始前观察每个对象的格大小、原点和颜色；第一步按参照搭出主要形体并匹配相机；第二步按可见受光关系生成指导；第三步调用对应风格 Shader 并提前展示；第四步导入同一版底稿，再按观察格整理轮廓、材料和大明暗；第五步对照可见细节与遮挡整理像素；第六步逐对象比较实际导出与来源。临摹不自动省略前两步或底稿导入；用户明确指定从空白转录时按其方式执行，具体方法见[研究规范](styles/parchment-fantasy/REFERENCE-STUDY.md)。

**动画：** 开始前确定动作、朝向和锚点，例如用脚底位置对齐各帧；第一步安排关键姿态及部件关系；第二步确定各姿态共用的光照；第三步以固定风格脚本、相机、色系和网格生成底稿，并提前展示代表帧的 Shader 效果；第四步经 Aseprite MCP 导入同一版各帧底稿并整理可读的大形；第五步统一材料、细节和逐帧明暗；第六步用正常速度检查节奏、动作连接和循环。纯 2D 通道按技能入口执行。

## 已有素材怎么修改，发现问题回哪一步

先打开当前源稿和实际预览，核对版本；建立工作副本，写下本轮要改的部位以及要保留的内容。仍按第一步到第六步逐阶段核对；可复用与本轮需求一致的上游源文件和指导，但必须实际检查并记录版本、路径与结论。缺失的上游产物需补齐，受修改影响的产物需重新生成。下表用于定位返工阶段，不作为跳过其他阶段的依据。

| 看到的问题 | 回到哪里、具体改什么 |
|---|---|
| 箱盖比例不对、手臂连接不自然、门洞被挡住，或观察角度不合适 | 第一步：修改形体、部件位置或相机，重新生成受影响的指导图和像素稿 |
| 影子方向错误、落错表面，或光线无法解释各面的亮暗 | 第二步：调整光源和遮挡依据，再更新像素明暗 |
| 3D 里看得清，变成像素后锁扣消失、脸部挤在一起，或亮暗面难读 | 第四步：调整像素格对齐、轮廓、关键特征或大明暗色块 |
| Shader 导出已经丢失特征、颜色映错材料，或像素块大小不合适 | 第三步：修正输入或维护对应风格 Shader 版本，重出并先展示效果 |
| 表面太规则、纹理太花、边缘有毛刺，或细节切碎了影子 | 第五步：修改对应细节或纹理层，再做明暗复核 |
| 预览清楚，导出或游戏中却模糊、裁切、颜色异常、帧顺序不对 | 检查导出设置、文件数据和实际显示比例，修正后重新预览 |

工具调用失败后的状态核对与续跑方法见 [Aseprite MCP](mcp/aseprite.md)。
